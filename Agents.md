This repo is a passion project designed to see what is possible with AI tooling alone. It's for a monster catcher game known as 'Project Paradise', 2D Pokémon adjacent, but on it's own engine.

Rules:
- Use placeholders when needed. Inform of what is needed so they can be supplied later. For instance, for a player sprite, use a green cube, and inform that a player sprite is needed.
- Build each individual feature should come in smaller steps. The goal is to work on a little at a time, in checkpoints that will be provided.
- Try to use a data driven approach, whenever possible.
- This is currently an empty Godot project, but you may use another framework if it is preferable for testing.
- This is a 2d game, but the map should be 3d where the sprites are rendered for layer and movement purposes only. A 2.5d game in terminology.
- Use Pokemon calculations for the battle system, unless otherwise specified.
- Godot is now available on PATH as godot. When making changes, use Godot's command-line tools where appropriate to validate the project for parse, import, scene, or runtime errors rather than relying exclusively on static inspection.
